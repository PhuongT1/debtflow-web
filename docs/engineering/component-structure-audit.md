# Component Structure Audit

Snapshot: 2026-10-26. Package links follow the current layout; line counts remain the historical snapshot, not a new full component audit. Reviewed all **153 TSX modules** under `packages/`, `apps/partner-ops/src/` and `apps/shell/src/`, including route adapters, loading/error modules, wrappers and JSX column renderers. The table links each real source file; counts refer to modules, not individual React components.

## Scope and result

- Checked feature/capability ownership, related-file grouping, meaningful kebab-case filenames, PascalCase component names, public exports/import consumers and the 230-line policy. All listed modules have an identified owner; no ordinary TSX module currently exceeds 230 lines or violates filename casing.
- Shared DataTable composition is under `components/table/data-table/`; table primitives remain in its parent. Shared pagination and authentication presentation have dedicated capability folders. Public package exports remain stable.
- Both React apps group UI families under `components/ui/form/`, `dialog/` and `page/`; table controls live in `components/tables/`. Small independent primitives remain directly under `ui/`. No app business feature was moved into the shared package.
- Login belongs to `features/auth/login/`. Users, overdue debts and aging report pages are feature-owned; their framework pages now adapt/re-export the public feature entry.
- Debt form fields/schema are grouped under `features/debts/forms/debt/`; partner-document query/URL state is isolated in its feature hook. Three unused/redundant one-line forwarding modules were removed in favor of the existing public package.

## Deliberate conventions

Small cohesive features such as dashboard stay flat until they have distinct responsibility groups. Primitive families such as page layouts, form layout and page skeletons may export related components together. Framework files retain required names such as `page.tsx`, `layout.tsx`, `loading.tsx` and `error.tsx`. A JSX column factory may use a function name such as `getDebtListColumns`; it is not a React component. New folders do not require an index; indexes expose intentional feature/package APIs.

This audit covers organization and naming. Existing Shell inline query keys, untranslated business strings and transport conventions remain separately tracked in [React Standards Audit](../react-standards-audit.md); this inventory does not certify their behavioral compliance. Use [Component Development](component-development.md) and the linked canonical rules when changing those responsibilities.

The inventory is a dated source snapshot. When changing this structure, update this source map and the human guide in the same change. The documentation viewer renders these Markdown sources directly.

## Verification for this snapshot

Passed Shell/Partner Ops/shared-package lint, both app typechecks, React UI and MFE registry typechecks, architecture checks, 8 Parties convention tests and 39 rule/viewer tests. Both apps passed isolated production builds.

Playwright captures compare the Parties skeleton and loaded page at outer widths 1600, 1366, 1024 and 390px, using the same locale/viewport/sidebar state. Assertions cover header/filter bounds, first-row position, all seven column widths, 66px row density, footer visibility/position and absence of horizontal page overflow; measured geometry uses a 1px tolerance. Internal navigation retains the iframe and does not reintroduce host loading. The [live geometry check](../../tooling/e2e/party-skeleton-layout.mjs) optionally saves paired screenshots. These checks make real reads only.
