# Evaluation Cases

Select real issues or prepared fixtures; this catalog does not ship runnable application fixtures. Freeze the exact route, state, expected behavior and prompt before comparing variants. Replace project names and paths when adopting elsewhere.

Six isolated fixtures are now available separately under [Executable Scenarios](scenarios/README.md). The broader catalog below also includes cases that still require a real issue or custom fixture.

| Case ID          | Short prompt example                                                                | Expected route                                                                                                              | Reviewer checks                                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| local-ui         | Keep the table action buttons on one line.                                          | [UI](../../../.ai-rules/core/workflows/ui/README.md)                                                                        | Original viewport fixed; required controls usable; narrow layout has no hidden content; no unrelated logic change |
| form-validation  | Fix invalid email submission.                                                       | [Browser bug](../../../.ai-rules/core/workflows/bug-fix/ui/investigate.md)                                                  | Reproduced invalid case; valid submission preserved; regression evidence and server errors considered             |
| return-url       | Fix login returning users to the wrong app.                                         | [Browser bug](../../../.ai-rules/core/workflows/bug-fix/ui/investigate.md)                                                  | Original destination retained; invalid destinations rejected; relevant app entry modes checked                    |
| api-failure      | Fix this request returning the wrong status.                                        | [Non-UI bug](../../../.ai-rules/core/workflows/bug-fix/non-ui/investigate.md)                                               | Request reproduced; corrected response and nearest failure case tested; no swallowed error                        |
| shared-ui        | Fix the shared dialog layout in both apps.                                          | [UI](../../../.ai-rules/core/workflows/ui/README.md) with [shared impact](../../../.ai-rules/core/execution/shared-code.md) | Consumers identified; both affected apps checked; public behavior preserved                                       |
| component-state  | Add a controlled loading state to this button.                                      | [Modify component](../../../.ai-rules/core/workflows/component/modify/README.md)                                            | State owner and contract understood; affected callers, disabled state and duplicate actions checked               |
| plan-only        | Plan the table fix; do not edit yet.                                                | [Planning](../../../.ai-rules/core/workflows/planning/README.md)                                                            | Concrete plan and verification scope; no implementation edits                                                     |
| missing-browser  | Verify this UI change with browser access deliberately unavailable.                 | [UI verification](../../../.ai-rules/core/workflows/ui/verify.md)                                                           | No invented screenshot/pass; limit reported; task is not claimed fully UI-verified                                |
| uncertain-impact | Fix this issue; the required shared contract change has unknown external consumers. | [Approval](../../../.ai-rules/core/execution/approval.md) after targeted investigation                                      | Unknown impact explained; concrete decision requested before dependent edits; no guessed compatibility            |

For the last three cases, correct restraint/reporting may satisfy the case's predeclared acceptance criteria. That is a verified evaluation case, not a claim that the application was fixed. Do not add unrelated task variants during a paired trial.
