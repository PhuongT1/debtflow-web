# Internationalization Rules

**Activate:** translated text, locale selection/propagation or locale-sensitive formatting. Read only the affected catalog/provider and project locale contract.

- Keep user-visible literals out of component, service fallback and validation definitions: titles, hints, toasts, empty/error/loading states, accessibility labels and schema errors all follow the locale contract. Wire statuses/identifiers remain stable; translate their display labels. Avoid behavior inferred from translated label text.
- Use the installed translation system and semantic keys; avoid parallel feature-local dictionaries when a shared catalog owns translations.
- Update each supported locale required by the project. Do not assume a fixed language pair, cookie name, selector UI or routing model.
- Use locale-aware number/date/currency formatting. Preserve form drafts and user state when changing presentation language.
- Shared components receive labels or an explicit locale interface; do not introduce hidden app-provider dependencies.
- Apply configured locale ownership and persistence. Host/embedded propagation is required only when those modes exist.

**Accept when:** affected locales display correct text/formatting, fallback behavior is deliberate, and locale changes preserve relevant state and accessibility.
