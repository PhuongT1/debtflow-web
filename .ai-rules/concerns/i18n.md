# Internationalization Rules

- User-visible text must use the application's established translation system; do not add feature-local string dictionaries.
- Keep translation keys semantic and namespaced by feature. Add the same key to every supported locale in the same change.
- Use locale-aware formatters for dates, numbers, and currency; do not manually concatenate locale-sensitive output.
- Locale is a global preference selected by the Shell. Propagate it to embedded MFEs through the versioned platform message contract without reloading the entire page.
- Standalone MFEs must initialize from their locale cookie/default and continue to work when no host is present.
